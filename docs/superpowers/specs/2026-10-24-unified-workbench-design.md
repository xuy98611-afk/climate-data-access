# 统一气候数据入口：第一版设计

用户已同意按“地区、时间、指标 → 来源 → 获取 → 核验 → 导出”建设自用工程。本设计将这一方向限定成可运行、可扩展的第一版。

## 方案选择

- 继续仅维护链接目录：维护成本低，但无法完成请求、获取与核验。
- **采用本地工作台 + Python 服务层 + 可插拔来源（本版）**：复用既有 ERA5 工具，先打通三个明确来源，再逐步增加连接器。无需服务器或额外订阅。
- 完整云端平台：需要部署、任务队列与多用户认证；超出当前个人使用需求。

## 第一版交付

1. 将 44 项目录随 Python 包发布，可按名称、指标、来源和账号条件检索。目录记录与可执行连接器分别标示。
2. 同一请求入口接受显式来源、起止日期、指标及点位或区域。结束时间始终不包含在结果内。ERA5 区域默认采用既有 GEE 原生网格方法；不自动切换供应商。
3. 三个执行路线：`era5-gee`（区域逐小时、原九变量）、`nasa-power`（点位逐日/逐小时）、`open-meteo`（显式固定 ERA5、点位逐小时）。后两者首先支持常用温湿、降水、风、气压、辐射变量；各自使用公开的原变量名。
4. 中文浏览器工作台仅监听本机回环地址。检索目录、填写请求、离线计划、小批获取、查看历史与核验；下载前必须先显示计划。ERA5 使用用户本机已有认证及其项目，不保存令牌。
5. 每次执行独立目录：原始响应、CSV（点位）或 NetCDF（区域）、请求及来源清单、SHA-256。点位缺测不补值、不丢行，以空单元格及缺测计数记录；区域 ERA5 保持既有严格合同，遇缺测拒绝该批，不发布成完整结果。核验是结构、一致性与来源核验，不宣称独立气象精度验证。
6. 保留 0.1 的原有 plan/fetch/verify/bundle 命令。新命令提供 catalog、request-plan、request-fetch、request-verify、serve。

## 结构与数据流

`catalogue.py` 负责包内目录；`requests.py` 校验统一请求；`providers.py` 定义点位能力、构造 URL 与解释返回；`transport.py` 有限时长和字节上限的 HTTPS；`service.py` 负责来源分派、持久化和回读核验；`web.py` 与 `web/index.html` 负责本地工作台。原 `config.py`、`gee.py` 和 `artifacts.py` 继续服务 ERA5。

输入 → 严格校验 → 离线计划 → 用户执行 → 固定来源获取 → 核对时间序列/变量/单位/缺测 → 原始响应和 CSV → 清单及 SHA → 可再次核验。

请求不接受任意 URL、密码或令牌。点位请求限定日期跨度、变量数、响应字节和输出预算。现有完整目录为只读。输出写入新的独立目录；不覆写研究库或用户已有文件。失败不会标为完成；重试由用户明确执行。服务器不提供任意路径读取；仅允许列出其固定输出根下的已知任务。POST 采用每次启动随机会话标识，并校验 Host/Origin。

## 开源工具的复用边界

- earthaccess：后续 NASA Earthdata 搜索、认证与下载首选；NASA POWER 使用其独立公开 API，本版不假称调用 Earthdata SDK。
- EODAG：后续多供应商遥感搜索下载接入候选；遵循其供应商/插件边界，按产品测试。
- earthkit-data：后续 GRIB、CDS、OPeNDAP 的读取与获取候选。
- Intake-ESM：后续 CMIP6 等模式目录筛选与 xarray 加载候选。
- Open-Meteo：本版实际接入其公开历史 API，固定 ERA5 模型，并保存返回网格坐标和处理约定。点位产品不能当作原生区域 ERA5 的等价替代。

这些库不会无目的地全部加入核心依赖；记录官方链接、适用范围、未来实现合同和验证门槛。

## 验收

- 原 18 项测试保留；新增请求边界、UTC/日界、缺测、错误响应、SHA 篡改、包内目录、HTTP 上限和本地页面 API 测试。
- 从构建后的 wheel 安装到隔离路径，验证 44 项目录和 HTML 均随包可用。
- NASA POWER 与 Open-Meteo 各做一个历史点位、少量时次的真实匿名端到端获取，并回读核验；不扩大为长期全产品承诺。
- ERA5 新统一层使用合成传输测试；若当前账号不满足条件，明确注明本版未重新进行真实 GEE 下载。
- 页面进行浏览器功能与窄屏检查。公开发布代码、文档和不含私密信息的核验摘要；本机数据、查询历史和凭据不提交。

## 后续需求如何接入

新增需求用一个请求 JSON 保存；新增供应商须声明空间形态、频率、变量、单位、时间约定、认证、限制和来源元数据，并增加实际响应核验及离线测试。只有通过实际测试的路线才能升级状态；44 项目录不等于 44 个已实现连接器。
