# 新增来源与适配器

先确定需要的产品、频率、空间选择与使用资格，再决定直接调用官方 API，还是封装成熟库。不要为了目录数量批量增加未验证的连接器。已有 44 项目录与可执行路线是两个层次；新增目录条目不自动获得执行能力。

## 当前代码契约

| 入口 | 当前约定 |
| --- | --- |
| requests.route_capabilities() | 返回 source、label、kind、frequencies、variables、auth，用于能力说明 |
| requests.plan_request(obj) | 完全离线；拒绝未知来源、未知字段和不支持范围；返回规范化 request、source、record_count、认证与空间/时间说明 |
| providers.provider_url(request) | 只为明确的点位来源构造官方固定 HTTPS 端点，不接受任意用户 URL |
| providers.interpret(raw, request) | 输入原始 bytes，输出 CSV bytes 与 units、missing_counts、provenance、record_count；严格校验上游结构与口径 |
| service.fetch_request(obj, directory, project=None, transport=None) | 规划后执行明确来源，要求新目录；transport 便于用合成响应隔离网络测试 |
| service.verify_request(directory) | 从原始成果独立回读，而非只相信之前的 passed 字段；按清单版本选择核验逻辑 |
| web.Workbench | 对页面执行“计划 → 当前参数匹配 → 单任务获取 → 记录 → 核验”，CLI 共享底层服务 |

这些函数是当前实现的接口，不是已发布的稳定插件协议。ERA5 使用 config / gee / artifacts 的独立格式；新增区域来源可以选择合适的独立成果格式，不必套入点位 CSV。

## 增加一条可执行路线

1. 明确来源标识、产品版本、覆盖、变量、原始单位、频率、UTC 或其他时间标准、累计区间、空间选择、缺失编码、认证与许可。优先核对官方文档并保存引用日期。
2. 在 requests.py 增加能力与离线校验。只放开已验证的字段、变量与范围，输出规范化请求；未知字段须拒绝，不能默默忽略改变口径的参数。
3. 新增提供者构造和解释逻辑，并在 service.py 显式分派。固定官方端点，限制响应与总体输出；适配器失败时显示原因，不自动换来源。
4. 设计可回读的成果与清单。保留原始响应或等价的明确原始成果，记录请求、来源、时间/坐标/单位、缺失和文件哈希；完成标记最后提交。核验须独立检查数据与清单的一致性。
5. 同步 route_capabilities、CLI 需要的参数、web.py、web/index.html 的来源/频率/变量与说明，以及目录条目的可执行路线映射。当前 UI 有显式选项和变量表，仅增加 Python 分支不够。
6. 增加离线测试，至少覆盖正常响应、日/小时边界、结束不包含、缺失、重复或乱序时间、单位变化、错误形状、超限响应、失败不完成、文件改动和认证缺失。避免只测试实现自己生成的理想响应。
7. 经用户授权后执行最小真实样本，记录实际产品、范围、变量、账号条件、返回元数据与核验结果；离线通过不能写成在线打通。更新[状态](status.md)、能力说明与示例。

目录本身的公开获取条件、历史入口核对与本次适配器验收分别记录，不覆盖历史证据来制造“全部已验证”的印象。

## 复用成熟库

[生态文档](ecosystem.md)列出 EODAG、earthaccess、earthkit-data 与 intake-esm 的用途。这些目前没有安装或接入。未来引入时采用适配器包装，保持本项目的离线计划、显式来源、成果清单与核验流程；不要把某个库宣称支持的所有提供者直接列成本项目已实现路线。

每项集成应指定兼容版本和可选依赖，验证实际调用的方法、认证路径、分页/限流、产品版本及结果坐标和时间。凭据留在用户本机的官方认证机制，不能写进请求 JSON、清单、日志、测试样本或公开仓库。SDK 自动重试、缓存或默认模型等行为须检查并明确记录，不能让默认值改变来源语义。
